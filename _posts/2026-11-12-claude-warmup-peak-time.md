[claude-warmup](https://jungtaejoon.github.io/claude-warmup/ko/)은 Claude Pro·Max의 5시간 창을 늘 켜 두는 작은 도구예요. 앞 창이 끝나면 바로 새 창을 열어 두니까, 언제 자리에 앉든 내 첫 메시지가 5시간짜리 기다림을 새로 시작하지 않아요.

그런데 써 보니 아쉬운 점이 하나 있었어요. 저는 매일 비슷한 시간에 일어나고, 일이 가장 몰리는 시간도 거의 같아요. 그렇다면 **그 시각에 딱 리셋**되는 게 제일 좋겠죠. 0.2 버전에서 이 기능을 넣었어요.

## 피크 시간이란

```bash
claude-warmup config peak 11:30 weekdays
```

"평일 11:30이 제일 바쁘다"고 알려 주면, 그 시각에 창이 끝나도록 핑 시각을 거꾸로 계산해요. 11:30에 리셋되려면 그 창은 06:30에 시작해야 하고, 그 앞 창은 01:30, 그 앞은 전날 20:30, 15:30이에요. 그래서 핑은 이 시각들에만 나가요(`hours` 설정 밖의 시각은 빼요).

| 쓰는 법 | 뜻 |
| --- | --- |
| `config peak 14:00` | 매일 14:00 |
| `config peak 11:30 weekdays` | 평일 11:30 (`평일`, `월-금`, `mon,wed,fri`도 돼요) |
| `config peak off` | 끄기 (원래대로 창을 끊김 없이 이어요) |

## 이렇게 동작해요

- **맞는 시각이 아니면 기다려요.** 엉뚱한 시각에 창을 열면 그 창이 피크를 어긋나게 만드니까요. 기다리는 동안에는 Claude를 부르지 않아서 토큰도 안 써요.
- **이미 어긋난 창은 어쩔 수 없어요.** 내가 다른 시각에 직접 메시지를 보내서 창이 열렸다면 그 창은 옮길 수 없어요. 그 창이 끝나면 다음 맞는 시각에 다시 맞춰요.
- **요일을 정하면 그 사이에는 원래대로 동작해요.** 피크 하루 전부터 맞추기 시작하고, 주말처럼 피크가 먼 시간에는 창이 끝나자마자 새 창을 열어요. 평일 11:30이면 금요일 오후부터 일요일 오전까지는 늘 켜 두기, 일요일 15:30부터는 월요일 11:30에 맞추기예요.
- **대신 기다리는 동안에는 열린 창이 없어요.** 그 사이에 내가 먼저 쓰기 시작하면 내 메시지가 창을 열어요. 이게 싫다면 피크 시간을 끄면 돼요.

상태 화면에서 바로 확인할 수 있어요.

```
자동 워밍업
  스케줄      06:00–23:00 · 매일
  피크 시간   평일 11:30 · 06:30, 15:30, 20:30에 맞춰 핑
  다음 핑     15:25경, 내일 11:30에 리셋되도록 맞춰서
```

## 업데이트하는 법

```bash
npm install -g github:jungtaejoon/claude-warmup
claude-warmup install
claude-warmup config peak 11:30 weekdays
```

`install`을 다시 실행해야 백그라운드 서비스가 새 버전으로 바뀌어요. `scripts/server-setup.sh`로 서버에 설치했다면 npm 명령에 `--prefix ~/.local`을 붙여야 같은 자리의 프로그램이 바뀌어요. 저도 처음에 이걸 빼먹어서 서버에서 옛 버전이 그대로 돌고 있었어요.

자세한 변경 내용은 [릴리스 노트](https://github.com/jungtaejoon/claude-warmup/releases/tag/v0.2.0)에 있어요.
